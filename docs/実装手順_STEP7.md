## STEP 7-0. 改行コードの正規化（1回だけ）

### 目的

Claude Code がファイルを書き直すと、実質2行の変更でもファイル全体が変わったように見えることがある（CRLF ↔ LF）。先に正規化しておくと、以降の差分が本当に変えた箇所だけになる。

### 指示

```
実装に入る前に、改行コードを正規化しておきたいです。

1. リポジトリ直下に .gitattributes を作成し、次の1行を書いてください。

* text=auto eol=lf

2. `git add --renormalize .` を実行し、変更内容を `chore: 改行コードをLFに統一` というメッセージでコミットしてください。

3. コミット後に `git status` が clean になっていること、`git diff HEAD~1 --stat` で何が変わったかを報告してください。

コードの中身は変更しないでください。
```

### 完了確認

- `.gitattributes` ができている / `git status` が clean

## STEP 7-3. お気に入り（端末内保存）

### 指示

```
STEP 7-3「お気に入り」を実装してください。仕様は docs/ジャンル追加仕様_v1.3.md の §5 に従ってください。**利用者ログインは導入しません。端末内（localStorage）に保存します。**

## 1. `lib/favorites.ts` に集約する

画面から直接 localStorage を触らないでください。将来ログイン方式に差し替えられるよう、このファイルだけを見ればよい状態にします。

- キー: `favorites:v1`
- 値: トレーニング id の配列（登録順。新しいものを先頭に積む）
- export する関数: `getFavorites()` / `toggleFavorite(id)` / `isFavorite(id)` / `removeFavorite(id)`
- **読み書きは必ず try/catch で囲む**（プライベートウィンドウ等で例外が出る）。失敗時は「0件」として正常に動くこと
- 保存する値は id のみ。題名などのコピーを持たないこと

## 2. お気に入りボタン（ハート）

- 一覧カードと詳細ページに置く
- localStorage はサーバーで読めないため**クライアントコンポーネント**にする。ハイドレーション前に未選択状態がちらつかないよう、useEffect で読み込んでから状態を反映すること
- 一覧カードのハートは、カードのリンク遷移を邪魔しないこと（stopPropagation / preventDefault）
- タップ領域は44px以上、aria-label とトグル状態（aria-pressed）を付ける

## 3. `/favorites`

- サーバー側で一覧（上限100件・全ジャンル）を取得し、クライアントで localStorage の id 配列に一致するものだけを表示する
- **ジャンル混在で表示**し、各カードに**ジャンルバッジ**（体遊び／リフティング）を出す
- 並び順は登録した順（新しいものが上）
- 検索・カテゴリー絞り込みは付けない
- 各カードから解除できる
- **取得結果に存在しない id（削除された種目）は表示せず、localStorage からも取り除く**（自己修復）
- 空状態: 「まだお気に入りがありません。気になる種目のハートを押すとここに入ります」＋各ジャンルへの導線
- 下部に小さく注意書き:
  「お気に入りはこの端末のブラウザに保存されます。別の端末やブラウザには引き継がれません。閲覧履歴を消すと消えることがあります。」
```

```
## 1. 追加・編集フォーム（/admin/new, /admin/[id]/edit）

- **フォームの一番上に「ジャンル」の選択タブ**を置く（体遊び／リフティング）。必須・単一選択

- そのジャンルにカテゴリーが1件も無い場合、「先にカテゴリーを登録してください」と表示し、/admin/categories への導線を出す

- genre: 必須。'body-play' | 'lifting'

- trainings の insert / update に genre を含める

- 保存・削除後の revalidatePath を **`/`（入口の件数表示）と `/list/[genre]` と該当詳細ページ**に対して呼ぶこと。ジャンルを変更した場合は**変更前と変更後の両方の一覧**を revalidate すること

## 4. /admin（トレーニング管理一覧）

- 上部に**ジャンル絞り込みタブ**（すべて／体遊び／リフティング）

- 「＋新しいトレーニング」は、絞り込み中のジャンルを初期選択した状態でフォームを開く

## 5. /admin/categories（カテゴリー管理）

- 上部に**ジャンルタブ**（体遊び／リフティング）。選んだジャンルのカテゴリーのみ表示
- 追加は**そのタブのジャンル**で登録される
- 編集できるのは name と sort_order のみ（slug は従来どおり編集不可。**genre も編集不可**）
- 削除条件は従来どおり（使用中は削除不可）
- slug の重複エラーは「そのジャンルではその slug は既に使われています」に変更（一意制約が (genre, slug) になったため）

npm run build が通ることを確認してください。
```

## 付録. 詰まったときの投げ方

- **ハートの状態がちらつく／リロード直後だけ未選択に見える**
  → 「localStorage はサーバーで読めないため、初回描画とハイドレーション後で表示がずれています。useEffect で読み込むまではニュートラル表示にして、ちらつきを消してください」

- **リフティングの種目が体遊びの一覧に出てしまう**
  → 「/list/[genre] のクエリに .eq('genre', genre) が入っているか、クライアント側のフィルタで漏れていないかを確認してください」

- **カテゴリーの slug が重複して登録できない**
  → 「categories の一意制約が (genre, slug) の複合になっているか確認してください」

- **管理画面で保存したのに一覧に出ない**
  → 「revalidatePath の対象が `/` のままになっていませんか。`/list/[genre]` と `/`（件数表示）の両方を再検証してください」

- **git の差分が実際より大きく見える（ファイル全体が変更扱い）**
  → 「改行コードが CRLF ↔ LF で入れ替わっています。.gitattributes に `* text=auto eol=lf` を入れて `git add --renormalize .` してください」

- **ファイルが削除できない／git の操作が失敗する**
  → `npm run dev` が動いたままか、VS Code・エクスプローラーがフォルダを掴んでいます。止めてから再実行してください。
