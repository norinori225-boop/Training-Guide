## 修正1. お気に入りのアイコンを『☆』に統一する

### 現状の問題

- 一覧カード・詳細ページのお気に入りボタンは **ハート（♡／♥）**
- 入口画面の「お気に入り」ボタンのアイコンは **星**

同じ機能なのに見た目が2種類あり、結びつかない。

### 決定

**すべて『☆』（星）に統一する。** ハートは使わない。

### 指示

```
お気に入りのアイコンを、アプリ全体で星（☆／★）に統一してください。

1. components/FavoriteButton.tsx の HeartIcon を StarIcon に置き換える
   - 未登録: 輪郭だけの星（fill なし・stroke あり）
   - 登録済み: 塗りつぶした星
   - **色だけで区別しない**という既存の方針は維持する（形も変える）
   - 色は現在の rose 系ではなく、星に合う amber 系（例: text-amber-500）にする。未登録は従来どおり控えめなグレー
   - aria-pressed / aria-label は現状のまま変更しない

2. 入口画面（app/(entry)/page.tsx）の「お気に入り」ボタンのアイコンも、
   同じ星の形にする。絵文字ではなく、FavoriteButton と同じ SVG を
   共通コンポーネント（例: components/StarIcon.tsx）に切り出して両方から使うこと。

3. ハート（Heart）という名前や形が残っていないか全体を検索して確認する。

見た目以外の動作（保存先・トグルの挙動）は変えないでください。
```

### 完了確認

- 一覧・詳細・入口画面のどこを見ても星
- 未登録＝輪郭、登録済み＝塗りつぶしで、色を見なくても区別がつく

## 修正2. 必要な道具「その他」に文字入力を追加する

### 現状の問題

管理画面の「必要な道具」で **【その他】にチェックはできるが、何なのか書けない**。
利用者側にも「その他」としか出ないため、情報として役に立たない。

### 決定

`trainings` に **`equipment_other`（自由入力欄）を1本追加**する。

- 道具のコード値（`none` / `ladder` / `cone` / `ball` / `other`）の仕組みは**変えない**
- 「その他」にチェックしたときだけ、道具名を自由に書ける
- 入力は **1つの欄**。複数ある場合は「なわとび・フープ」のように区切って書く運用にする（欄を増やさない）
- 上限は **30文字**
- 利用者側では「その他」ではなく、**入力された名前をそのまま表示**する
- キーワード検索の対象にも含める（「なわとび」で引けるように）

### 指示（その1: データベース）

```
「必要な道具」の【その他】に、道具名を自由入力できるようにします。
まず DB を変更してください。supabase/migrations/ に新しい SQL ファイルを作ります。

## trainings に列を追加

- equipment_other text（null 許可）
- コメント: 「道具に 'other' を選んだときの自由入力欄。表示・検索ではコード値 'other' の代わりにこの文字列を使う」

## 制約

1. 文字数: null でなければ、前後の空白を除いて1〜30文字
   check (equipment_other is null or char_length(btrim(equipment_other)) between 1 and 30)

2. 整合性: equipment に 'other' を含むときだけ値が入る（含まないなら必ず null）
   check ( ('other' = any(equipment)) = (equipment_other is not null) )

## 重要: 既存データの backfill を先に行うこと

すでに equipment に 'other' を含む種目があると、上の整合性チェックを
付けた瞬間にエラーになります。制約を追加する**前に**、次を実行してください。

update public.trainings
set equipment_other = 'その他の道具'
where 'other' = any(equipment) and equipment_other is null;

（あとで管理画面から正しい名前に直せるよう、仮の値を入れておく方針です）

## その他

- 何度実行しても同じ結果になる（冪等）ように書くこと
- 適用後の確認SQL（'other' を含む行と equipment_other の対応が取れているか）を
  README に追記すること
- lib/types.ts の Training 型に equipment_other を追加すること

適用は私が Supabase の SQL Editor で行います。SQL を作るところまでで止めてください。
```

### 指示（その2: フォームと表示）

```
DB の変更が済んだので、アプリ側を対応させてください。

## 1. バリデーション（lib/schemas.ts）

- equipment_other: 任意の文字列。前後の空白を trim する
- **equipment に 'other' を含む場合は必須**（1〜30文字）
  - 未入力なら「その他の道具の名前を入力してください」
  - 31文字以上なら「30文字以内で入力してください」
- **equipment に 'other' を含まない場合は null にして保存する**（チェックを外したら値を捨てる）
- 既存の「'none' を含む場合は要素数1のみ」という排他ルールは変更しない

## 2. 管理フォーム（components/TrainingForm.tsx）

- 「その他」のチェックボックスにチェックが入ったときだけ、**すぐ下にテキスト入力欄を出す**
  - ラベル: 「その他の道具の名前」
  - プレースホルダー: 「例: なわとび・フープ」
  - 補足文: 「複数ある場合は「・」で区切って書いてください」
- チェックを外したら入力欄を隠し、値もクリアする
- 「道具なし」を選んだときは（既存の排他制御で）「その他」も外れるので、
  入力欄も消えること
- 編集時は保存済みの値が初期表示されること
- 入力欄も最低44pxの高さにする（スマホで押しやすく）

## 3. 利用者側の表示

道具の表示名を作る箇所を1つの関数にまとめ、全画面がそれを使うようにしてください
（lib/constants.ts か lib/queries.ts に `equipmentLabels(training)` のような形）。

- equipment のコード値を表示名に変換する
- ただし 'other' のときは「その他」ではなく **equipment_other の値**を出す
- 一覧カード（先頭2件＋N の省略）、詳細ページ（全件）の両方でこの関数を使う

## 4. キーワード検索

- 検索対象に equipment_other を追加する（小文字化した部分一致）
- 「なわとび」で、その道具を使う種目がヒットすること

npm run build が通ることを確認してください。
```

### 完了確認

- 管理画面で「その他」にチェックすると入力欄が出る／外すと消える
- 名前を入れずに保存しようとするとエラーになる
- 一覧カードと詳細ページに、「その他」ではなく入力した道具名が出る
- その道具名でキーワード検索してヒットする
- 「道具なし」を選ぶと「その他」も入力欄も消える
