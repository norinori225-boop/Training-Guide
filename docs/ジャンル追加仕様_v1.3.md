# ジャンル追加 仕様追補（v1.3）— 入口画面／体遊び・リフティング／お気に入り

- 作成: 2026-08-26
- 位置づけ: **要件定義書 v1.2 への追補**。ここに書いた内容が v1.2 と矛盾する場合、こちらが優先。
- 対象: すでに稼働中のアプリ（Next.js + Supabase + Vercel、PWA化済み）への**後付け改修**

---

## 0. 何を変えるか（要約）

「**ジャンル**」という上位の軸を1本追加する。

```
【変更前】 ホーム(一覧) ──▶ 詳細

【変更後】 入口画面 ──▶ 体遊びトレーニング 一覧 ──▶ 詳細
              ├──▶ リフティングトレーニング 一覧 ──▶ 詳細
              └──▶ お気に入り ──▶ 詳細
```

- 既存の一覧画面（検索・カテゴリーチップ・カード）の**中身はそのまま**、ジャンルごとに1画面ずつ持つ形にする
- 既存のカテゴリー6分類（速く走る／バランス…）は**体遊び専用**になる。リフティングは別のカテゴリーを持つ
- 管理画面のフォームに「ジャンル」選択を足し、選んだジャンルの一覧に出るようにする

## 0.1 決定事項（2026-08-26）

| # | 論点 | 決定 |
|---|---|---|
| 1 | ジャンルとカテゴリーの関係 | **カテゴリーをジャンルごとに分ける**（categories に genre 列を持たせる） |
| 2 | 既存の登録済み種目 | **すべて『体遊び』に割り当てる** |
| 3 | お気に入りの保存先 | **端末内（localStorage）**。利用者ログインは導入しない |
| 4 | 入口の見せ方 | **3つの大きなボタンを並べた入口画面**（下部固定タブバーではない） |
| 5 | リフティング用カテゴリー | **『トラップ』『コントロール』の2つ**でスタート |
| 6 | アプリ名・PWA名称 | **今回は変更しない**（後日変更予定・名称は未定） |
| 7 | 先行作業（未コミット分） | **破棄して、この仕様どおりに作り直す** |
| 8 | ジャンル別一覧の URL | **`/list/[genre]`**（`/training/[id]` と紛らわしくならないように） |

## 1. ジャンルの定義

ジャンルは**コードで固定**する。管理画面から追加・削除はできない（画面構造そのものが変わるため）。

| コード値 | 表示名 | 短縮表示 |
|---|---|---|
| `body-play` | 体遊びトレーニング | 体遊び |
| `lifting` | リフティングトレーニング | リフティング |

- `lib/constants.ts` に `GENRES` として定義し、他ファイルは必ずここを参照する（表示名のハードコード禁止）
- 3つ目のジャンルを増やす場合はコード変更＋マイグレーションが必要。**当面2つで確定**
- 「お気に入り」はジャンルではない。入口画面に並ぶ3つ目のボタンだが、データ上の扱いは別物（§5）

## 2. データモデル（STEP 7-1 で適用済み）

### 2.1 `trainings.genre`

- `'body-play'` / `'lifting'` の CHECK 制約つき text、not null
- 既存行はすべて `'body-play'`
- **default は付けない**（明示指定を必須にして、指定漏れの誤登録を防ぐ）
- インデックス `trainings(genre, created_at desc)`

### 2.2 `categories.genre`

- 同上。既存の6カテゴリーはすべて `'body-play'`
- **一意制約を張り替え済み**
  - 変更前: `name` unique / `slug` unique（アプリ全体で一意）
  - 変更後: **`(genre, name)` unique / `(genre, slug)` unique**
  - 理由: リフティング側にも「バランス」など同じ名前・slug を使いたくなるため
- `sort_order` はジャンル内での並び順

### 2.3 `training_categories`（テーブル定義は変更なし）

次の**不変条件**を守る。

> **トレーニングに紐づくカテゴリーは、すべてそのトレーニングと同じ genre のものでなければならない。**

サーバー側（Server Action）で必ず検証する。

### 2.4 リフティング用の初期カテゴリー

| sort_order | name | slug |
|---|---|---|
| 1 | トラップ | trap |
| 2 | コントロール | control |

- 2つでスタート。管理画面から追加・編集できるので、種目が増えてから足せばよい
- 1種目に**両方を付けることもできる**（多対多のため）
- ⚠️ ジャンルにカテゴリーが0件だと種目を登録できない（カテゴリー1件以上必須のため）

## 3. URL 設計

| URL | 内容 | 備考 |
|---|---|---|
| `/` | **入口画面**（3ボタン） | 現在の一覧ページを置き換える |
| `/list/[genre]` | ジャンル別の一覧 | 現在の一覧（`app/(home)/page.tsx`）の中身をここへ移設 |
| `/favorites` | お気に入り一覧 | |
| `/training/[id]` | 詳細 | **変更なし**（既存のブックマーク・共有リンクが生きる） |
| `/admin/*` | 管理画面 | パスは変更なし。中身にジャンル選択を追加（§6） |

- 不正な genre（例: `/list/xxx`）は `notFound()` で404
- PWA の `start_url` は `/` のままでよい
- **`/trainings` は使わない。** 詳細の `/training/[id]` と1文字違いになり、リンクの書き間違いが404として現れて原因が分かりにくいため

## 4. 画面仕様（利用者側）

### 4.1 入口画面 `/`

- アプリのロゴ／タイトル（**アプリ名は現状のまま**）
- **縦に3つの大きなボタン**（タップ領域は十分に大きく、スマホ幅で押しやすいこと）
  1. 体遊びトレーニング → `/list/body-play`
  2. リフティングトレーニング → `/list/lifting`
  3. お気に入り → `/favorites`
- 各ボタンにアイコンと1行の短い説明
- 各ボタンに**そのジャンルの登録件数**を出す（例: 「12種目」）
  - `fetchTrainingCount(genre)` を使い、`count: 'exact', head: true` で**行は取らず件数だけ**数える
  - お気に入りの件数はクライアント側で数える（0件のときは出さない）
- 「**使い方**」の3ステップを置く
- フッターに安全に関する注意書き（既存の `SafetyNotice` を流用）
- フッターに「**管理者ログイン**」の**目立たない**導線
- 検索欄は置かない（ジャンルを選んでから検索する）

### 4.2 ジャンル別一覧 `/list/[genre]`

**現在の一覧（`app/(home)/page.tsx`）の中身をそのまま持ってくる。** 変更点は次のとおり。

- 画面上部にジャンル名の見出しと、**入口へ戻る導線**（「← ホーム」）
- 表示対象を `genre` で絞る（`.eq('genre', genre)`）
- カテゴリーチップは**そのジャンルのカテゴリーのみ**（「すべて」＋該当カテゴリー）
- キーワード検索の対象は既存どおり（題名／簡単な説明／詳しい説明／カテゴリー名／道具の表示名）。ただし**同一ジャンル内のみ**
- 各カードに**お気に入りボタン（ハート）**を追加（§5）
- 空状態を2種類に分ける
  - そのジャンルにまだ種目が無い → 「準備中です」
  - 検索・絞り込みで0件 → 「すべて表示に戻る」導線つき空状態
- 管理者ログインの導線は入口ページへ移すので、ここには置かない

### 4.3 詳細 `/training/[id]`

- 既存のまま。追加するのは次の2点
  - **お気に入りボタン**（§5）
  - 「もどる」の遷移先: 履歴があれば戻る。**直リンクで開かれた場合はそのトレーニングの genre の一覧へ**

### 4.4 お気に入り `/favorites`

- 端末内に保存された種目を、**ジャンル混在で**一覧表示する
- カードには**ジャンルバッジ**（体遊び／リフティング）を出す
- 並び順: 登録した順（新しいものが上）
- 検索・カテゴリー絞り込みは**付けない**
- 空状態: 「まだお気に入りがありません。気になる種目のハートを押すとここに入ります」＋各ジャンルへの導線
- 各カードから解除できる

## 5. お気に入りの実装方式

**端末内（localStorage）に保存する。ログインは導入しない。**

- キー: `favorites:v1`
- 値: トレーニング id の配列（登録順。新しいものを先頭に積む）
- 読み書きは必ず try/catch で囲む（プライベートウィンドウ等で例外が出るため）。読めない場合は「0件」として正常に描画する
- localStorage はサーバーでは読めないため、**お気に入りに関わる部分はクライアントコンポーネント**にする。ハイドレーション前のちらつきを避けるため、`useEffect` で読み込んでから状態を反映する
- `/favorites` の取得: サーバーで一覧（上限100件）を取得し、クライアントで id 配列に一致するものだけ表示する
- **削除された種目の id が残る問題**: 取得結果に存在しない id は表示せず、localStorage からも取り除く（自己修復）

### 5.1 利用者への明示

お気に入り一覧の下部に、小さく注意書きを出す。

> お気に入りはこの端末のブラウザに保存されます。別の端末やブラウザには引き継がれません。閲覧履歴を消すと消えることがあります。

### 5.2 将来のログイン導入に備えて

- 保存する値は **id の配列のみ**（表示名などのコピーを持たない）
- 読み書きは `lib/favorites.ts` の関数（`getFavorites()` / `toggleFavorite(id)` / `isFavorite(id)` / `removeFavorite(id)`）に集約し、画面から直接 localStorage を触らない

## 6. 画面仕様（管理者側）

### 6.1 追加・編集フォーム `/admin/new`, `/admin/[id]/edit`

- **フォームの一番上に「ジャンル」選択タブ**（体遊び／リフティング）。必須・単一選択
- ジャンルを選ぶと、**カテゴリーのチェックボックス一覧が該当ジャンルのものに切り替わる**
- **ジャンルを切り替えたら、選択済みのカテゴリーはクリアする**。カテゴリーを選んだ後の切り替えは「カテゴリーの選択が外れます」と確認する
- 編集時も同様（ジャンル変更は可能。カテゴリーは選び直し）
- サーバー側検証:
  - genre が必須で、`body-play` / `lifting` のいずれか
  - **categoryIds がすべて選択ジャンルのカテゴリーであること**（違反時「選択したジャンルと異なるカテゴリーが含まれています」）
- そのジャンルにカテゴリーが0件なら「先にカテゴリーを登録してください」＋カテゴリー管理への導線

### 6.2 トレーニング管理一覧 `/admin`

- 上部に**ジャンル絞り込みタブ**（すべて／体遊び／リフティング）
- 各行に**ジャンル**列を追加
- 「＋新しいトレーニング」は、絞り込み中のジャンルを初期選択して開く

### 6.3 カテゴリー管理 `/admin/categories`

- 上部に**ジャンルタブ**。選んだジャンルのカテゴリーのみ表示
- 追加は**そのタブのジャンル**で登録される
- 編集できるのは `name` と `sort_order` のみ（slug・genre は変更不可）
- 削除条件は従来どおり（使用中は削除不可）
- slug の重複エラーは「そのジャンルではその slug は既に使われています」

## 7. 既存仕様との衝突・見直し点

| # | 既存の記述 | 対応 |
|---|---|---|
| 1 | 「ホームから**3タップ以内**で動画に到達」 | **「入口→一覧→詳細」の3タップで詳細に到達**（動画再生を含めて4タップ）に緩和 |
| 2 | `categories.name` / `slug` がアプリ全体で unique | **`(genre, name)` / `(genre, slug)` の複合 unique に変更**（§2.2） |
| 3 | 「お気に入り」は将来拡張 | **MVP後の第1弾機能として実装**（端末内保存の範囲で） |
| 4 | PWA のアプリ名「アジリティートレーニング」 | **今回は変更しない**（§7.1 に手順を残す） |
| 5 | 既存の `/`（一覧）へのブックマーク | `/` は入口画面に変わる。`/training/[id]` は不変なので共有済みリンクは生きる |
| 6 | 「1クエリ全件取得→サーバー側フィルタ」 | 方針は維持。ジャンル絞り込みはクエリ側の `.eq('genre', genre)` |

### 7.1 アプリ名を後日変更するときの手順

名称が決まったら、次の3か所を直す。1か所でも漏れると端末によって古い名前が残る。

1. `app/manifest.ts` の `name`（Android・PC用）と `short_name`（ホーム画面表示用）
2. `app/layout.tsx` の `metadata.appleWebApp.title`（**iOS はここしか見ない**）
3. `metadata.title`（ブラウザのタブ・共有時の表示）

変更後、スマホでは**ホーム画面のアイコンを一度削除してから追加し直す**こと。

### 7.2 改行コードの扱い

Claude Code がファイルを書き直すと、実質2行の変更でも git 上はファイル全体が変更されたように見えることがある（CRLF ↔ LF の入れ替わり）。`.gitattributes` に `* text=auto eol=lf` を置いて正規化しておく。
